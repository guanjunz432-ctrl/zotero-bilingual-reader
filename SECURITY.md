# Security reports

For credential exposure or a vulnerability, use this repository's GitHub **Security → Report a vulnerability** private reporting route when available. Do not post tokens, cookies, authentication files, private papers or raw account errors in public issues.

If private reporting is unavailable, create an issue that says only that a private contact route is needed; do not include exploit details or identifying data. Never send a maintainer your login file to reproduce an issue.

Supported line: the current 0.1 preview. The project is experimental; reports will be assessed without a promised response deadline.

The intended boundary is a local translation client with isolated official login, restricted agent tools, and no project-operated relay. A page requesting commands, credentials or external access is untrusted document content, not an instruction.
